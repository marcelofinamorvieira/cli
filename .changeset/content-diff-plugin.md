Add the `content:diff` and `content:apply` commands for moving content between DatoCMS environments or projects. `content:diff` checks that the two schemas are structurally compatible, refuses source records the CMA reports invalid (except invalid drafts in models that allow them), compares the content and writes an editable TypeScript migration of ordinary CMA calls in dependency order, with a sibling `.content` directory recording the destination baseline. `content:apply` refuses to run if the destination changed since generation, then executes the script in a new fork by default (or in place with `--in-place`), deletes the fork if the script fails, and reports CMA validation errors with the request that caused them. Generated updates lock to the destination version seen at generation, sortable and tree order is set with one `reorderRecords` call per group that gains records or changes order, and assets are copied from their source URL with an MD5 check. Requires Node.js 22.23.1+ on the 22.x line, or 24.18+.
